# skill-test-workflow 使用说明

当你要测试、评估、对比或改进某个技能时使用本技能。

## 常见用法

```text
测试 animation-flow 技能，看看它是否会把演示产物放到正确目录。
```

```text
用同一个 prompt 对比使用 dev-workflow 和不使用 dev-workflow 的结果，并记录观察。
```

```text
跑一下某个技能的 evals，把测试记录和生成文件按仓库约定保存好。
```

## 默认输出位置

- 测试记录：`test-results/<被测技能名>/`
- 运行产物：`outputs/<被测技能名>/`
- 可复用 eval：`skills/<被测技能名>/evals/`

## 最小真实样例

如果被测技能会生成文件、目录、截图、导出物、代码或 demo，测试时必须在 `outputs/<被测技能名>/<本次测试>/` 下跑出一个最小真实样例。

静态检查只能作为补充，不能替代运行产物测试。若技能因为确认门禁或外部依赖无法跑完整流程，要保存真实停点产物并说明原因。

## 推荐命名

文件名固定带 3 位零填充序号（从 `001` 起，每次都带），序号针对「同一天 + 同一短描述」独立递增，避免同一天多次测试互相覆盖：

```text
test-results/<技能名>/2026-06-29-basic-001.md
outputs/<技能名>/2026-06-29-basic-001/
```

同一天同一短描述再测一次则用 `002`、`003`；另起一个短描述（如 `ab-comparison`）则重新从 `001` 开始。多轮迭代测试短描述统一用 `iteration`，由序号承担轮次区分。

A/B 对比时：

```text
outputs/<技能名>/2026-06-29-ab-comparison-001/
  with-skill/
  without-skill/
```

## 注意

不要把技能测试生成的截图、导出物、临时 demo 或中间文件放进 `skills/<技能名>/`。只有技能源码、说明、eval 和可复用资源才应该留在 `skills/` 中。
